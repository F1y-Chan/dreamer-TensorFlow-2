## 0. 先说清楚：这个项目是什么、不是什么

**是什么**

- 2019 年 Dreamer v1 论文 *Dream to Control: Learning Behaviors by Latent Imagination* 的 TensorFlow 2 精简复现。
- 一个**基于模型的强化学习（MBRL）**智能体：先学一个"世界模型"，再在模型内部"想象"未来轨迹来训练策略。
- 单智能体、**图像观测**（64×64×3）、**连续动作**（DMC 的 MuJoCo 任务）或离散动作（Atari）。
- 代码量很小：5 个 `.py` 文件约 1900 行，核心 `dreamer.py` 526 行。这一点对新手极其友好——你能在一天内读完整个算法。

**不是什么（重要，避免走弯路）**

| 你可能以为 | 实际情况 |
|---|---|
| 这是无人机/编队项目 | 不是。它只认 `dmc_*` 和 `atari_*` 任务，环境和无人机无关 |
| 这是 Dreamer v2 / v3 | 是 **v1**。没有离散隐变量、没有 KL balancing、没有 symlog/two-hot/percentile 归一化 |
| 多智能体框架 | 完全单智能体。`config.envs` 只是并行跑多个**独立**环境副本，不是多智能体 |
| 观测是状态向量 | 它**强制**要求 `obs['image']`，编码器写死了 CNN |

所以你真正要做的事是：**读懂它的骨架（世界模型 + 想象训练），然后把"图像单智能体"换成"状态向量多智能体"**。第 7 节给了完整路线。

## 3. 一次训练循环到底发生了什么

### 3.1 两个嵌套的循环

```
main()                                   ← 外层：环境交互（慢循环）
 ├─ prefill: 随机动作跑 5000 步，存 npz
 ├─ agent = Dreamer(...)
 └─ while step < 5e6:
     ├─ 评估 1 个 episode（training=False，动作取分布众数，无噪声）
     ├─ simulate(agent, ..., steps=5000)  ← 收集 5000 个 transition
     │    └─ 每 1000 环境步，__call__ 里触发 train
     │         └─ 内层：train(100 步)       ← 梯度更新（快循环）
     └─ 保存 variables.pkl
```

**关键理解**：训练是"数据驱动"的，不是"步数驱动"的。`self._step`（`dreamer.py:114`）是从 `episodes/` 目录里的文件名统计出来的（`count_episodes`），所以：

- 往目录里放 npz = 假装训练过；
- 删掉 npz = 训练进度回退；
- `train_every=1000` 表示"每新增 1000 环境步，做 100 次梯度更新"。

### 3.2 数据从哪来、长什么样

一次环境交互产生一个 **transition**：`{image: (64,64,3) uint8, action: (A,), reward: (), discount: ()}`。
一个 episode 结束时，`wrappers.Collect`（`wrappers.py:150`）把它堆成数组存成 `episodes/<时间戳>-<uuid>-<长度>.npz`。

`RewardObs`（`wrappers.py:334`）干了一件很巧的事：**把 reward 塞进 observation dict**。这样 `data['reward']` 就在 batch 里，世界模型可以直接监督奖励预测。（你以后换环境也必须保持这个约定。）

`tools.load_episodes` 是一个**无限生成器**：每次随机挑 `train_steps=100` 条 episode，每条随机切 `batch_length=25` 长的片段。所以 `tf.data` 每 `next()` 一次拿到 `25 × 25` 的数据。

### 3.3 `_train()` 的三个阶段（`dreamer.py:188`）

```
        ┌── 阶段 1：世界模型 ─────────────────────────────┐
        图像 ──encode──> embed (B,T,1024)
             ──RSSM.observe──> post, prior (各 B,T,{mean,std,stoch,deter})
             ──get_feat──> feat (B,T,230)
             ├─ decode(feat)   → 重建图像    损失：负对数似然
             ├─ reward(feat)   → 重建奖励    损失：负对数似然（Normal std=1 ≈ MSE）
             └─ KL(post ‖ prior)            损失：+ kl_scale × max(KL, free_nats)
        └────────────────────────────────────────────────┘
        ┌── 阶段 2：Actor（策略） ────────────────────────┐
        从 post 展平出发 ──imagine 15 步──> imag_feat (15, B·L, 230)
             ├─ reward(imag_feat).mode()
             ├─ value(imag_feat).mode()
             └─ lambda_return(...) → returns
             actor_loss = -mean(cumprod(pcont) × returns)
        └────────────────────────────────────────────────┘
        ┌── 阶段 3：Critic（价值） ───────────────────────┐
        value_loss = -mean(cumprod(pcont) × value_pred.log_prob(stop_grad(returns)))
        └────────────────────────────────────────────────┘
```

对应代码：阶段 1 在 `193–219` 行，阶段 2 在 `225–241` 行，阶段 3 在 `246–250` 行，三个优化器在 `253–255` 行。

### 3.4 三个损失各自的含义

| 损失 | 代码 | 公式 | 直觉 |
|---|---|---|---|
| 世界模型 | `dreamer.py:218` | `kl_scale·max(KL, 3) − (log p(图) + log p(奖励))` | 既要重建得像，又要隐状态可预测 |
| Actor | `dreamer.py:240` | `−E[Π discount · λ-return]` | 让想象出来的回报越大越好 |
| Critic | `dreamer.py:249` | `−E[Π discount · log p(target)]` | 把价值网络拟合到 λ-return 上 |

关于 `free_nats = 3.0`（`dreamer.py:216`）：KL 项低于 3 nats 就不罚了。这是 v1 的"防塌缩"手段——否则模型会偷懒让后验直接等于先验（不看观测），重建也能勉强达标，但隐状态就没有信息了。

## 4. RSSM 精讲（整个框架的心脏）

### 4.1 状态是什么

隐状态由两部分拼成（`models.py:53`）：

```
state = { deter: h_t (200 维, GRU 记忆) , stoch: z_t (30 维, 随机变量) }
feat  = concat(z_t, h_t)  → 230 维   ← 下游所有网络（解码器/奖励/价值/策略）都吃它
```

- `h_t` 负责**确定性**的长时记忆（"我一直在往北飞"）；
- `z_t` 负责**随机性/不确定性**（"第 3 架飞机现在到底偏了几米，我不确定"）。
- 两者缺一不可：只有 h 学不了多模态未来，只有 z 记不住长历史。

### 4.2 两个 step：先验 vs 后验

```
img_step(prev_state, prev_action)          models.py:74
    x = concat(prev_state.stoch, prev_action)
    x = Dense(200, elu)(x)
    x, h = GRUCell(200)(x, prev_state.deter)
    x = Dense(200, elu)(x) → Dense(60) → mean, std
    prior = {mean, std, stoch: sample, deter: h}
    ↑ 不看观测。用于"想象"和"预测"。

obs_step(prev_state, prev_action, embed)   models.py:61
    prior = img_step(...)                  ← 先猜
    x = concat(prior.deter, embed)         ← 再偷看观测
    post  = {mean, std, stoch, deter: prior.deter}
    ↑ 这就是"后验"。用于训练和在线推理。
```

`std = softplus(x) + 0.1`（两处都有）——保证方差恒正且有下界。

### 4.3 observe / imagine

- `observe(embed, action)`（`models.py:30`）：把 `(B,T,...)` 转置成 `(T,B,...)`，用 `static_scan` 沿时间展开 T 步，**同时**返回后验序列 `post` 和先验序列 `prior`。因为有观测，这是"有老师教"的路径。
- `imagine(action, state)`（`models.py:44`）：只调 `img_step`，没有任何 embed。这是"闭着眼睛做梦"，Dreamer 的行为学习全靠它。

> ⚠️ `static_scan`（`tools.py:395`）是 **Python for 循环 + tf.stack**，图会随 T 线性膨胀。所以 `batch_length=25`、`horizon=15` 不能随便调大——这直接对应显存和编译时间。

### 4.4 为什么用 KL(post‖prior) 而不是别的

训练时后验能看观测，先验不能。让先验去逼近后验 = 把"我看不到观测时的猜测"训练得接近"看到观测后的真相"。这样部署/想象时（只有先验）才不会失真。方向不能反。

## 5. 想象与 λ-return

### 5.1 `_imagine_ahead`（`dreamer.py:327`）

```python
start = post 展平 (B·L, 30)            # 真实轨迹的后验状态
states = static_scan(                  # 展开 horizon=15 步
    lambda prev, _: self._dynamics.img_step(prev, policy(prev)),
    tf.range(horizon), start)
```

两个容易看漏的点：

- `post` 是 `(B, L, 30)`，展平成 `(B·L, 30)` 后**每个时间步都当成一条独立想象的起点**。所以一次训练其实在想象 `B × L = 25 × 25 = 625` 条轨迹，每条 15 步——这就是 Dreamer 样本效率的来源（一次真实数据，反复榨取）。
- `policy` 里用了 `tf.stop_gradient(get_feat(state))`（`dreamer.py:333`）：**选动作时不传播梯度**，只有后面的 actor loss 才通过动作传播。这是为了让 actor 的梯度路径干净。

### 5.2 λ-return（`tools.py:316`）

```
λ=1 → 蒙特卡洛（用满 15 步回报，方差大偏差小）
λ=0 → 单步 TD（用价值网络自举，方差小偏差大）
本仓库 λ=0.95（config.disclam）
```

`bootstrap=value[-1]` 是第 15 步之后的"尾巴"，用价值网络补上。

### 5.3 那个 `cumprod` 是干什么的（`dreamer.py:238`）

```python
discount = cumprod([1, pcont[:-2]])
```

分两种情况：

- **`pcont=False`（本仓库默认，`dreamer.py:63`）**：`pcont` 恒为 `0.99 * ones`（`dreamer.py:232`），`cumprod` 就退化成普通的 $0.99^t$ 折扣。此时终止信息只作用到 `bootstrap` 上。
- **`pcont=True`**：`pcont` 由数据学出"这一步之后是否还继续"，真实终止时它接近 0，`cumprod` 就会把终止之后的回报清零，不再计入 actor/critic 损失。

**做无人机任务时如果你的 episode 会因碰撞提前终止，建议开 `--pcont True`**，否则策略会学到"撞了还能继续拿分"的错觉。

## 7. 迁移到"异构无人机编队控制"

这是本文最重要的部分。先给你一张差异对照表，再给分阶段路线。

### 7.1 差异对照

| 维度 | 本框架（现状） | 你的任务（目标） | 影响 |

| 智能体数 | 1 | N（同构或异构） | 联合状态/动作，或 CTDE |

   ```python
   # 原来：图像专用，会把状态向量除以 255 再减 0.5，直接毁掉数据
   # obs['image'] = tf.cast(obs['image'], dtype) / 255.0 - 0.5

   # 改成：按你自己的观测统计量做标准化（或干脆只转 dtype）
   obs['image'] = tf.cast(obs['image'], dtype)
   ```

   更稳的做法是固定一组 `mean/std` 常数（在 prefill 的 5000 步数据上统计一次），训练全程复用。

3. **`dreamer.py:433` `make_env()`** 加一个分支：

   ```python
   elif suite == 'uav':
     env = wrappers.PointDrone()
     env = wrappers.ActionRepeat(env, config.action_repeat)
   ```
   然后用 `--task uav_hover` 启动（`task.split('_', 1)` 会切成 `('uav', 'hover')`）。

4. **`models.py` 加状态编码器**（替换 `ConvEncoder`）：

   ```python
   class StateEncoder(tools.Module):
     def __init__(self, size=256, act=tf.nn.elu):
       self._size, self._act = size, act
     def __call__(self, obs):
       x = obs['image']                       # 就是状态向量
       x = self.get('h1', tfkl.Dense, 2 * self._size, self._act)(x)
       x = self.get('h2', tfkl.Dense, self._size, self._act)(x)
       return x
   ```

5. **`dreamer.py:273,276`** 换掉编解码器：

   ```python
   self._encode = models.StateEncoder(self._c.num_units)
   ...
   self._decode = models.DenseDecoder((STATE_DIM,), 2, self._c.num_units, act=act)
   ```
   `likes.image = image_pred.log_prob(data['image'])` 这行**不用改**——`DenseDecoder` 形状改了，log_prob 自动对上。

**验证标准**：`test/return` 明显高于随机策略，且 `div`（KL）不塌到 0。做到这一步，你就把 Dreamer 从"图像"解绑了，后面才好动多智能体。

> 顺带的好处：状态向量输入后，参数量从 630 万降到几十万，训练快一个数量级，你可以在笔记本上做消融实验。

### 7.3 M1：同构编队 = "一个超级智能体"（最稳的第一步）

**核心思想（强烈建议从这里开始）**：把 N 架无人机的联合状态当作一个大状态、联合动作当作一个大动作，**完全不动算法**。

```
joint_state  = concat(s_1, ..., s_N)          # 例如 N=4, 每机 12 维 → 48 维
joint_action = concat(a_1, ..., a_N)          # 例如 N=4, 每机 3 维 → 12 维
reward       = f(编队误差, 碰撞, 能耗, 平滑度)
```

- 优点：改动量几乎是常数（只写环境和奖励），跑通即可得到 baseline，审稿人也认（"centralized Dreamer"）。
- 缺点：N 增大时动作维线性膨胀，探索效率下降；不能直接泛化到没见过 N。
- 工程提示：`_actdim` 会自动从 `action_space.shape[0]` 取（`dreamer.py:109`），所以只要你把 `action_space` 定成 12 维，actor 自动就是 12 维，**零代码改动**。

### 7.4 M2：加"异构"（三种做法，按难度排）

**A. 维度补齐 + 掩码（最简单）**
把所有机型的动作都补齐到最大维度 `A_max`，用一个 `mask` 表示哪些维有效，无效维在 `step()` 里丢弃。观测里加一个 `type_one_hot`（如 `[1,0]` = 四旋翼，`[0,1]` = 固定翼）。
- 改：环境 + 观测拼接。算法零改动。
- 缺点：浪费一点网络容量；掩码处理不干净会学到"无效维也能影响奖励"的假相关。

**B. 每类一个 actor（`ActionDecoder` 复制 N_type 份）**
共享世界模型，按 type 选 actor。改 `_build_model`（加 `self._actors = {type: ActionDecoder(...)}`）、`policy`（按 `obs['type']` 路由）、`_imagine_ahead`（想象时需要知道每步的 type，可以把它当作常量输入）。
- 优点：干净，不同动作维/不同分布都能表达。
- 代价：改动最大，要小心 `tools.Adam` 的变量列表和 `save/load`（`variables.pkl` 会整体序列化，结构变了旧 ckpt 全废）。

**C. 共享 actor + type embedding（折中，论文里常见）**
把 `type_one_hot` 拼到 `feat` 后面再喂 actor。改动极小，且能共享动力学知识。
- 推荐：**A 起步验证流程，C 做正式实验，B 留到需要极致性能时**。

### 7.5 M3：去中心化执行（CTDE，真正的"多智能体世界模型"）

到这里就进入研究区了，先想清楚一个设计问题：**世界模型建模的是"谁"的状态？**

| 方案 | 世界模型 | 执行 | 难度 | 适合的论文故事 |
|---|---|---|---|---|
| 联合模型 + 中心化执行 | 联合状态 | 中心算完再分发 | 低（=M1） | 集中式 baseline |
| 联合模型 + 分散执行 | 联合状态，各机共享 | 每机只看自己的隐状态切片 | 中 | **CTDE**：训练用全局，执行用局部 |
| 每机独立模型 + 通信 | 每机一个 RSSM | 传隐状态当"消息" | 高 | 通信式协同、可扩展 N |

"M3 中间那行"的具体做法：世界模型在联合状态上训练（数据好拿、样本效率高）；执行时每架飞机用自己的观测 + 邻居发来的隐状态消息 `z_j` 拼成输入，跑一个**共享的** actor。这样训练集中、执行分散，是当前多智能体 MBRL 最主流的路子。

### 7.6 奖励设计（最容易翻车的地方）

Dreamer 的奖励头是 `Normal(mean, 1)`，损失≈MSE。**奖励量级必须 O(1)**，否则奖励预测学不动，整条链路崩。建议：

```python
reward = (
    - w1 * 队形误差(位置 RMSE，归一化到米/期望间距)
    - w2 * 速度一致性误差
    - w3 * 碰撞惩罚(每对距离 < d_safe 计一次)
    - w4 * 控制能量(||a||²)
    - w5 * 动作变化率(||a_t - a_{t-1}||²)     # 平滑，真机上必加
)
```
总体把单步奖励控制在 `[-1, 1]` 量级，episode 回报自然在 `[-1000, 0]` 或 `[0, ~1000]`，和 DMC 的尺度一致，超参几乎不用重调。

### 7.7 评估指标（写论文用）

| 指标 | 说明 |
|---|---|
| 队形误差 | 期望相对位置 vs 实际相对位置的 RMS，随时间曲线 |
| 收敛时间 | 达到目标误差阈值的步数 |
| 碰撞率 | 每 episode 碰撞次数 / 最小机间距离 |
| 能耗 | 累计 `||a||²` 或推力平方和 |
| 鲁棒性 | 加风扰/传感器噪声/单机失效后的恢复能力 |
| 可扩展性 | N = 3, 5, 8 时性能衰减 |
| 样本效率 | 达到某分数所需环境步（Dreamer 的主打卖点，一定要和 MAPPO 比） |

### 7.8 如果时间紧：先想清楚要不要"必须用 Dreamer"

- 若目标是**发一篇编队控制的应用论文**：MAPPO / HAPPO 成熟得多，调参资料多，撞坑少。
- 若目标是**世界模型/样本效率的方法论文**：Dreamer 路线是对的，且建议直接看 **DreamerV3**（离散隐变量 + symlog/two-hot + percentile 归一化，对奖励尺度极不敏感，正是多智能体奖励难设计的解药）。
- 若你想"两边都要"：用 M1 的集中式 Dreamer 当 sample-efficiency 的卖点，用 MAPPO 当 baseline。

## 9. 坑位清单（血泪版）

1. **TF 版本**：`from tensorflow.keras.mixed_precision import experimental as prec` 在 TF ≥ 2.9 没有。不要 `pip install -U tensorflow`。
2. **gym 版本**：旧 API。gym ≥ 0.26 的 `reset()` 返回 tuple，`Collect.reset()` 会崩。
3. **dm_control on Windows**：`MUJOCO_GL=glfw` 需要交互式桌面；远程/无头会 `render` 失败。做无人机时**尽早摆脱 dm_control**，用自己的环境或 pybullet。
4. **数据集 schema 来自第一条 episode**（`dreamer.py:401`）：`types/shapes` 是从 `next(load_episodes(...))` 推断的。你改了观测键名/维度后，**必须清空 `logdir/*/episodes/` 再跑**，否则会报 shape 不匹配的诡异错误。
5. **`episodes/` 就是经验池**：无限增长（压缩 npz，5000 步约几十 MB）。长期训练要么定期归档，要么换 `ReplayBuffer`。
6. **删 episodes = 重置进度**：`count_steps` 靠文件名里的长度统计。
7. **`MirroredStrategy`**：单卡也有额外开销和一堆 `num_replicas_in_sync` 除法。单卡调试可以直接删掉 strategy，但注意 `_train` 里三处 `/ float(...)` 要一起删。
8. **混合精度**：`precision=16` 时用 `LossScaleOptimizer`。如果出现 `NaN` 或损失不降，先改 `--precision 32` 排除数值问题。
9. **奖励尺度**：> O(10) 就会学不动（见 7.6）。
10. **`horizon` 太大**：`static_scan` 是 Python 循环，图会爆炸，编译时间飙升；15 是论文默认，别轻易上 50。
11. **随机种子**：`config.seed` 只影响 agent 内的 numpy RandomState 和一部分采样；TF 全局种子没设，严格复现要自己补 `tf.random.set_seed`。
12. **`pcont`**：默认 `False`（`dreamer.py:63`），此时 `discount` 只有固定折扣。若你的任务有真实终止（碰撞），建议开启 `--pcont True` 并保留 `pcont_scale=10`。
